# Guidance for test files

Consult [the vitest-testing skill](../.agents/skills/vitest-testing/SKILL.md) when authoring, reviewing, or debugging tests, choosing a test boundary, or investigating persistence, account, async, or browser behavior. Its references hold detailed procedures and the version baseline.

- Put Node tests in `tests/unit/` as `*.unit.test.ts` or `*.unit.test.tsx`; the unit project discovers `tests/**/*.unit.test.{ts,tsx}`. Put real-browser component/provider tests in `tests/browser/` as `*.browser.test.tsx`; the browser project discovers `tests/browser/**/*.browser.test.tsx`, mounts with `vitest-browser-react`, and uses headless Chromium via Playwright's installed Chrome channel. Put complete app flows in `tests/e2e/` as `*.spec.ts`, using the Playwright runner and `./fixtures` exports. Keep shared helpers at the tests root without executable test suffixes.
- Assert meaningful observable outcomes and intended contracts, with independent expectations and relevant failure cases. Name tests after their trigger/result. Preserve blank lines after imports and between declarations; prefer typed fixtures over broad casts. Trivial edits do not automatically need tests; avoid duplicating assertions across all layers.
- Reuse `tests/task-fixtures.ts` and `tests/guest-storage.ts` where appropriate. E2E `tests/e2e/fixtures.ts` defaults to a guest session; install account routes and storage before navigation. Isolate storage, accounts, listeners, timers, and database resources. Keep DB suites on isolated test databases; mocked persistence does not prove database correctness.
- Run targeted non-watch checks: `npm run test:unit -- <file>`, `npm run test:browser -- <file>`, or `npm run test:e2e -- <file>`. `npm test` runs all three in order; `npm run test:account` runs only account-persistence, account-data-source, and guest-import unit files. E2E builds and starts a fresh production server on port 3100. Broaden when warranted and check types for changed TypeScript. Documentation-only changes need document validation rather than full app execution.
- Confirm intended files/tests actually execute and inspect counts. `test:browser` uses `--passWithNoTests`, so exit success alone is insufficient. Remove accidental focused tests; do not weaken assertions, add unexplained skips, auto-accept snapshots, or add retries to conceal failures. Review snapshot differences. Report passed, failed, skipped, and blocked checks accurately; keep generated failure artifacts out of commits.
